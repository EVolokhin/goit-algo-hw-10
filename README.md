# Завдання 1: Порівняльний аналіз алгоритмів видачі решти

Розглянуто дві стратегії видачі решти для набору монет `[50, 25, 10, 5, 2, 1]`:
**жадібний алгоритм** (`find_coins_greedy`) та **динамічне програмування**
(`find_min_coins`).

## 1. Часова та просторова складність

| Алгоритм | Часова складність | Просторова складність |
| --- | --- | --- |
| **Жадібний (`find_coins_greedy`)** | $\mathcal{O}(N)$, де $N$ — кількість номіналів | $\mathcal{O}(1)$ додаткової пам'яті |
| **Динамічне програмування (`find_min_coins`)** | $\mathcal{O}(A \times N)$, де $A$ — сума, а $N$ — кількість номіналів | $\mathcal{O}(A)$ додаткової пам'яті |

## 2. Продуктивність при великих сумах

### Жадібний алгоритм

Оскільки кількість номіналів фіксована ($N = 6$), алгоритм виконує сталу
кількість ітерацій незалежно від суми $A$.

- Для $A = 100$ обчислення займає частки мікросекунди.
- Для $A = 10{,}000{,}000$ час виконання залишається практично незмінним
  ($\mathcal{O}(1)$ відносно $A$), оскільки використовуються лише арифметичні
  операції цілочисельного ділення та взяття остачі (`//` і `%`).

### Динамічне програмування

Час виконання та обсяг оперативної пам'яті зростають лінійно залежно від суми
$A$.

- Для суми $A = 1{,}000{,}000$ потрібно створити масив із $10^6$ елементів і
  виконати $6 \times 10^6$ ітерацій внутрішнього циклу.
- Для великих сум це призводить до значних витрат пам'яті та сповільнення
  роботи. При $A > 10^8$ можлива помилка через вичерпання пам'яті.

## 3. Точність та оптимальність розв'язку

### Канонічна система монет

Набір `[50, 25, 10, 5, 2, 1]` є *канонічним*. Для такої системи жадібний
алгоритм гарантовано знаходить глобально оптимальний розв'язок — мінімальну
кількість монет.

### Неканонічна система монет

Якщо змінити набір номіналів, наприклад, на `[40, 30, 1]`, то для суми `60`:

- **Жадібний алгоритм** поверне `{40: 1, 1: 20}` — разом 21 монету.
- **Динамічне програмування** знайде оптимальний варіант `{30: 2}` — разом
  2 монети.

## Висновки

1. Для касових систем із канонічними номіналами жадібний алгоритм зазвичай є
   найефективнішим: він працює швидко та потребує сталої додаткової пам'яті.
2. Динамічне програмування підходить для довільних, зокрема неканонічних,
   наборів монет. Однак для великих сум його застосування обмежене лінійним
   зростанням витрат пам'яті $\mathcal{O}(A)$ і часу $\mathcal{O}(A \times N)$.
